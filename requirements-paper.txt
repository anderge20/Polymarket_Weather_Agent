# ============================================================
# PAPER MODE requirements  (R22/R23/R24 — GitHub Actions cron)
# ============================================================
# Deliberately minimal, and that is the point: this file is installed on EVERY
# scheduled run, several times a day, on the free Actions tier. Installing the
# full pipeline tier (pandas + numpy + scipy + scikit-learn) would add minutes of
# wheel resolution per run to import nothing the cycle uses.
#
# Inspecting the Python import graph is NOT sufficient here, and assuming it was
# cost a failed Actions run. `pytz` appears in no `import` statement anywhere in
# this tree, yet DuckDB's native extension loads it at RUNTIME to materialise a
# TIMESTAMPTZ into a Python object. Every one of these tables has TIMESTAMPTZ
# columns, so the very first `dump_table` died with:
#     _duckdb.InvalidInputException: Required module 'pytz' failed to import
# It passed locally only because pytz happened to be installed. A native
# extension's runtime dependencies do not show up in a grep for `import`.
#
# Install:  pip install -r requirements-paper.txt

duckdb>=1.1            # the derived store; shards are rebuilt into it each run
requests>=2.32         # public gamma / CLOB / data-api GETs and POSTs
pytz>=2024.1           # NOT imported by our code: DuckDB needs it to hand back TIMESTAMPTZ

# NOT here, and not by omission:
#   * no wallet, signer, web3 or py-clob-client — gate D0 is structural, and the
#     paper engine must remain incapable of placing an order (tests assert it).
#   * no scipy/sklearn — the calibration work belongs to the backtest tier.
